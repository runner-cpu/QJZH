# 青境智衡（QJZH）

青境智衡是一个面向环境监测数据的本地优先分析工作台。它把数据导入、质量检查、风险判读、情景模拟和可审阅报告串成一条可追溯的浏览器工作流。项目可以直接在 GitHub Pages 上体验，也可以下载到本地运行；默认演示数据仅用于展示界面与计算流程。

## 在线体验

- 主页：<https://runner-cpu.github.io/QJZH/>
- 在线自检：<https://runner-cpu.github.io/QJZH/online_test.html>
- 发布构建信息：<https://runner-cpu.github.io/QJZH/build_info.js>

页面不需要账号，不会把导入的 CSV 上传到远程服务。默认数据保存在当前浏览器，刷新后仍然保留；受限浏览器会降级到标签页会话存储或页面内存。数据接入页显示当前存储方式，只有内存模式会在刷新时丢失数据。

## 项目边界

本项目用于数据整理、指标计算、规则解释和报告预览，不替代法定检测、专业审查或现场处置。输出结果是可解释的风险提示，不是诊断结论、合规结论或处置指令。使用者应核对原始记录、采样条件、单位和时间范围，并由具备相应权限的人员做最终判断。

## 六个工作视图

1. **总览**：查看数据规模、风险分布、质量概况和当前计算批次。
2. **数据接入**：导入 CSV、检查表头与字段约束、查看拒绝原因，并在提交前预览记录。
3. **算法解释**：逐项查看规则、权重、置信度和触发依据；每次导入都会重新计算派生值。
4. **机构/区域分析**：按区域或分析单元聚合指标，比较样本量、风险水平和数据完整度。
5. **情景模拟**：调整可解释的输入因子，观察风险等级与建议动作的变化。
6. **报告**：生成可打印、可保存的摘要报告，包含数据范围、限制说明、计算时间和免责声明。

## 快速开始

直接打开在线主页即可查看演示数据。若要使用自己的数据：

1. 进入“数据接入”。
2. 下载页面提供的 CSV 模板，或按下方字段创建 UTF-8 CSV 文件。
3. 选择文件并等待预检结果；所有错误都会在提交前显示。
4. 确认记录数、时间范围和单位无误后导入。
5. 在“算法解释”核对触发规则，在“报告”导出结果。

## 本地运行

项目是静态前端，不需要构建后端。建议使用任意静态文件服务器，避免浏览器对本地文件的模块和资源策略产生差异。

~~~text
git clone https://github.com/runner-cpu/QJZH.git
cd QJZH
python -m http.server 8080
~~~

然后访问 <http://localhost:8080/>。也可以使用 Node、Nginx 或其他静态服务器指向本目录。

## CSV 数据格式

最小字段集合如下，字段名必须完全匹配模板：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| timestamp | ISO-8601 时间 | 必须包含 `Z` 或 `+08:00` 等时区偏移 |
| site_id | 文本 | 2–64 位字母、数字、下划线或连字符的稳定标识 |
| altitude_m | 数值（m） | 模型输入，允许范围 2200–3500 |
| temp_c | 数值（℃） | 模型输入，允许范围 -15–25 |
| rh_percent | 数值（%RH） | 模型输入，允许范围 20–85 |
| raw_nh3_ppm | 数值（ppm） | 未校准氨气输入，允许范围 0–30 |
| device_model | 文本 | 设备或数据来源名称 |

导入器会拒绝空表头、重复表头、缺失字段、保留字段名、非法日历时间、错误引号、列数不一致和无法安全解析的行。未知列和派生列会被忽略，并在校验详情中列出。派生指标由当前版本算法重新计算；数值接近模型范围但超出的情况会标为 B 级警告，超出范围宽度 10% 以上的输入会被拒绝。

### 输入硬限制

- 文件大小不超过 1 MiB；
- 数据行不超过 5,000 行；
- 字段数量不超过模板定义；
- 单个字段长度不超过 256 个字符；
- 空文件和只有表头的文件不作为有效数据集。
- 当前浏览器累计最多保存 5,000 条记录，超限会拒绝整批保存，避免静默截断历史；同一站点的等价时区时间按同一时刻去重。

这些限制用于保持浏览器响应速度、避免意外资源消耗，并减少不完整输入进入分析流程的机会。完整字段、可选字段和最小示例见[数据字典](docs/DATA_DICTIONARY.md)。

## 数据生命周期与隐私

CSV 在浏览器内解析，预览确认后写入当前浏览器存储。页面会显示有效行、拒绝行及最多 20 条错误详情；部分有效文件只在确认后合并有效行。加载示例会替换全部业务数据，已有用户记录时需要确认。批量写入失败会尝试恢复原值，并区分恢复成功和恢复不完整。

使用敏感数据前，请先脱敏站点名称、坐标、人员信息和内部编号。浏览器本地存储不是备份，需要保留的数据应导出。只有内存降级模式在关闭或刷新后无法恢复。

## 算法与可信度边界

计算由规则库、决策引擎、补偿引擎、模型权重和模拟器共同完成。界面会展示输入摘要、触发规则、权重、置信度和限制说明，帮助审阅者复算关键结论。

置信度表示当前规则与输入质量下的相对可信程度，不等同于统计显著性、检测准确率或未来事件概率。缺失值、异常值、样本量不足、时间范围过窄和单位错误都会降低解释价值。任何结论都应结合原始记录与领域知识复核。

算法核心文件由原创清单保护。对核心实现的更改必须同步更新文档、测试和原创清单；发布前会验证文件哈希和许可证条款。

## 质量检查与发布

本地发布前建议依次执行：

~~~text
node scripts/verify-originality.js
node verify_compensator.js
node --test tests/*.test.js
node scripts/build-pages.js --out dist
node verify-deployment.js dist
git diff --check
~~~

真实浏览器检查使用开发依赖，产品运行仍是静态 HTML/JS，不依赖 Node 或 npm。首次运行检查时执行：

~~~text
npm ci --ignore-scripts
npx playwright install chromium
npm run test:browser
~~~

检查会启动临时本地服务器，以 `/QJZH/` 子路径访问构建产物，验证三种语言 × 两种主题 × 三种屏宽 × 六个视图共 108 组组合，以及导入确认、下载、刷新保留、机构汇总、报告弹窗降级、跨标签页同步和受限存储。截图与 JSON 证据写入 `output/browser-audit/`，不进入 Pages。GitHub Actions 使用同一套检查，失败会阻止部署。

scripts/build-pages.js 只复制明确列出的运行时文件和公开文档，不会把测试、备份、临时输出或内部计划目录带到 Pages。构建会生成 build_info.js，其中包含提交 SHA、构建时间和环境标识，便于线上回溯。

### 版本字段如何阅读

页面和报告会分别显示发布版本、部署版本、模型版本与规则版本：发布版本用于静态资源缓存，部署版本标识一次构建，模型版本对应锁定权重，规则版本对应知识库及其 SHA-256 指纹。`version` 仅为旧集成保留的部署版本别名；需要复核线上内容时，应优先记录 `build_info.js` 中的完整 `commit`、`builtAt` 和 `artifact-manifest.json`。

部署自检页把信息按复核顺序分成“构建来源”“版本身份”和“规则完整性指纹”三个区域：版本身份内部再分为“发布与部署”（缓存键与 CI 构建实例）和“执行契约”（模型接口与规则集）。规则 SHA-256 单列为内容证据，不与版本号混用；颜色只用于辅助分组，复核时应以可复制的文本字段、完整提交 SHA、UTC 构建时间和 SHA-256 为准。窄屏会按同一语义顺序堆叠，避免不同身份被连续色卡混淆。
