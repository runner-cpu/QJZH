# QJZH 发布质量与本地数据保护加固设计

## 1. 目标

本轮以“全面工程加固 + 小幅可访问性/体验优化”为范围，提升静态分析工作台在异常输入、浏览器存储受限、网络不稳定和重复复核场景下的可解释性与可恢复性。最终结果必须继续通过 GitHub Actions 的 allowlist artifact 发布，并能用线上构建 SHA 追溯到源提交。

## 2. 不变约束

- 不修改 `knowledgeBase.js`、`decisionEngine.js`、`compensator_engine.js`、`model_weights.js`、`simulator.js` 的算法内容。
- 保持六个 hash 视图、中文/英文/藏文、现有模型加载顺序和补偿模型锁定校验。
- 不新增上传服务、账号系统、远程数据库或硬件控制。
- 不使用禁用右键、阻断键盘、破坏屏幕阅读器或恶意反爬脚本。
- 公开文案只描述中性产品和工程边界，不写入任何未授权背景信息。

## 3. 当前问题与处理策略

### 3.1 输入与存储

文件选择目前主要依赖浏览器读取回调；异常读取、超大文件和用户取消操作的反馈不够统一。保存多个站点时，逐站点写入可能在配额不足时留下部分结果。

处理策略：

1. 在创建 `FileReader` 前检查文件大小、名称和可读性；在 `onerror`、`onabort` 和空文件分支返回结构化错误。
2. 让导入状态同时更新可见状态、`aria-busy` 和焦点目标，并复用现有三语翻译入口。
3. 保存前建立受控快照；写入失败时回滚本次批次涉及的业务键，并返回明确的存储模式和恢复提示。
4. 提供浏览器端 CSV 导出入口，导出只读取当前本地记录；清除操作增加确认和结果提示。
5. 文档明确区分 `localStorage`、`sessionStorage` 和内存模式，说明刷新、关闭页面和主动清除的差异。

### 3.2 动态内容与前端安全

当前多个视图使用动态 HTML 更新。已有部分转义逻辑，但缺少集中式回归约束，后续文案或字段扩展容易漏掉边界。

处理策略：

1. 保持已有安全转义函数的行为，补齐动态记录、报告摘要、机构筛选和错误详情的测试样例。
2. 对来自 CSV、localStorage、URL hash 和报告输入的值执行“文本节点或转义字符串”约束；禁止新增未审计的 HTML 拼接点。
3. 增加 `.well-known/security.txt`，并在安全文档中说明报告渠道、数据边界和响应期望。
4. 增加浏览器安全元数据和外部脚本完整性契约；不引入会破坏现有内联布局的激进 CSP。

### 3.3 可访问性与多语言

错误处理模块仍有固定语言文案，导入和报告状态的动态更新需要更一致地通知辅助技术。

处理策略：

1. 将错误状态、重试按钮、存储降级提示和导出结果接入 `ui_text_map.js`/现有翻译函数。
2. 为异步操作设置 `aria-busy`，完成或失败后把焦点移到状态摘要；保留键盘可操作路径。
3. 在语言切换时同步根元素 `lang`、页面标题、状态摘要和表格空状态。
4. 增加中文、英文、藏文三种语言下的状态键覆盖测试，以及动态内容不产生未转义标记的回归测试。

### 3.4 可重复性与性能

演示层部分展示值使用非确定性随机数，不利于截图、报告和缺陷复核；关键前端文件较大，但尚无预算契约。

处理策略：

1. 仅对未锁定的演示展示随机值使用基于记录时间和场景标识的轻量确定性种子；不改变锁定模拟器和算法输出。
2. 增加关键资源大小预算、脚本顺序、defer、SRI 和 CDN 失败提示测试。
3. 保留现有 Chart.js 固定版本和 SRI；对图表不可用时继续使用已有文本/Canvas 降级。

### 3.5 发布与运维

发布工作流已经使用 verified artifact，但仍可加强环境稳定性、文件边界和部署后的可观测性。

处理策略：

1. 在 CI 显式设置 `TZ=UTC`，执行完整测试、语法检查、生成文档一致性和 `git diff --check`。
2. 构建时生成 allowlist 文件清单与 SHA-256 摘要，验证 artifact 不含测试、临时目录、历史草稿或本地输出。
3. 部署后用带重试的 HTTP smoke test 检查主页、自检页、版权/原创/安全文档、数据字典、构建元数据和 robots/sitemap。
4. 强制检查线上 `build_info.commit` 等于 workflow HEAD SHA；Pages source 继续保持 `workflow`。

### 3.6 仓库与文档治理

根目录历史任务草稿和执行记录对运行时没有作用，且会增加公开仓库的审阅噪声。

处理策略：

1. 删除未被运行时、测试或发布脚本引用的历史任务草稿；保留公开用户指南、字段字典、发布清单、版权、原创和安全说明。
2. 更新 README 与用户指南，记录导出、清除、存储降级、复核和故障排查流程。
3. 保持原创清单覆盖核心实现、构建器和安全校验脚本；每次受保护文件变化都重新生成清单。

## 4. 组件与接口

- `dataImport.js`：扩展文件预检、读取错误、批次回滚、导出和清除确认接口。
- `errorHandler.js`：增加翻译键、焦点和异步状态契约。
- `ui_text_map.js`：补齐导入、存储、导出、重试和安全状态的三语键。
- `dashboard.js` / `ui_interactions.js`：接入状态反馈和确定性展示随机值；不改变锁定算法调用。
- `index.html`：补充安全元数据、状态关联属性和导出/清除控件契约。
- `scripts/build-pages.js`：输出 artifact 清单与摘要，并拒绝未允许的路径。
- `.github/workflows/verify-compensator.yml`：增加 UTC、边界检查和部署后 smoke test。
- `tests/`：覆盖输入、存储、XSS、语言、可访问性、确定性、构建边界和线上配置。

## 5. 失败处理与回滚

- 文件读取失败：不写入任何记录，显示可翻译错误和重试入口。
- 存储配额失败：回滚本次批次，保留原有记录，切换到已有降级模式并显示警告。
- 导出失败：不清除数据，显示可复用错误状态。
- 构建或 smoke test 失败：阻止 Pages 部署，不生成新的发布证据。
- 线上构建 SHA 不匹配：标记发布失败，先修复 Pages source 或 workflow，不手工覆盖 `build_info.js`。

## 6. 验收标准

1. 五个锁定算法文件内容哈希不变。
2. 完整 Node 测试、模型锁定校验、原创清单校验、源代码/产物部署校验和语法检查全部通过。
3. 受控恶意字段不会产生 HTML 标记，三语状态键无缺失。
4. 文件读取、存储回滚、导出、清除和确定性展示均有自动化回归。
5. Pages artifact 只含 allowlist 文件，线上公开路径返回 200，内部路径不发布。
6. 线上 `build_info.commit` 与最终远端提交 SHA 一致。
7. README、用户指南、数据字典和发布清单与实际行为一致。

## 7. 实施顺序

先同步远端并建立基线；然后按“输入/存储 → 状态与多语言 → 安全测试 → 构建/CI → 文档治理”的顺序实施。每个阶段先补回归测试，再改实现，最后运行完整验证并通过 GitHub Actions 发布。
