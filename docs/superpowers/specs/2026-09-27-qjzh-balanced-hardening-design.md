# 青境智衡均衡收官设计

日期：2026-09-27

基线：`gh-pages` / `b9effef`

状态：用户已批准“均衡收官”方向

## 1. 背景与目标

青境智衡当前已具备六视图 SPA、三语切换、高原氨气补偿演示、机构汇总、环境报告、打印与 GitHub Pages 发布能力。第 8 轮体检确认现有测试全部通过，但真实浏览器、数据链路和发布流程仍有若干会影响公开可信度与生产质量的问题。

本轮目标是在不改动锁定算法实现、不重写框架的前提下，同时完成四件事：

1. 让外部数据不能伪造系统校准结果，报告、机构版和决策视图使用一致且可追溯的风险口径。
2. 让 320–2560 px、键盘、读屏、深浅主题和中英藏三语场景都能稳定使用。
3. 提高首屏性能、图表交互和公开演示质量，同时保持现有绿色高原科技风格。
4. 让验证真正成为 Pages 发布前置门禁，并为线上版本提供准确的构建信息和搜索发现性。

## 2. 方案选择

审计后比较了三条路线：

- **可信数据优先**：只处理 CSV、存储、报告、风险口径和日期问题。改动最稳，但移动端和可访问性缺口仍会直接暴露。
- **展示体验优先**：集中处理移动端、图表、三语、无障碍和视觉层级。展示提升明显，但仍允许伪造派生值，报告结论不够可信。
- **均衡收官**：以数据可信为第一层、体验与无障碍为第二层、性能和发布治理为第三层。

采用第三条路线。它覆盖公开使用时最容易暴露的问题，也补齐影响后续维护的基础工程能力。为控制风险，本轮不加入账号、云端同步、多租户、模型重训、自动硬件控制或未经完整缓存设计的 Service Worker。

## 3. 不可变约束

以下五个锁定文件保持字节级不变：

- `knowledgeBase.js`
- `decisionEngine.js`
- `compensator_engine.js`
- `model_weights.js`
- `simulator.js`

现有补偿器输入输出和模型权重不改。展示层与报告层通过适配代码统一口径。现有深浅主题、绿色/青色主色、玻璃面板、六视图路由、三语和打印入口继续保留。

## 4. 数据可信设计

### 4.1 CSV 边界与派生字段

导入器只接受明确白名单中的原始字段和元数据字段。`calibrated_nh3_ppm`、风险等级、建议、模型版本等系统派生字段即使出现在 CSV 中，也不能覆盖系统计算结果。外部系统如确需携带自己的派生值，只能进入带 `external_` 前缀的独立字段，并标记来源；本轮页面不把这些字段作为决策依据。

每条被接受的数据记录经过统一规范化：

- `site_id` 需满足长度和字符约束，分组使用 `Map` 或无原型对象，避免 `__proto__`、`constructor` 等键破坏结构。
- `timestamp` 必须可解析为带时区的 ISO 8601 时间，不接受无效日期或明显未来时间。
- 数值字段沿用现有业务范围校验；拒绝项进入拒绝统计，不混入报告。
- 记录增加 `provenance`，至少区分 `user-import`、`manual-entry`、`sample` 与 `simulation`。

报告和机构汇总永远从原始输入重新调用现有锁定补偿模型。缓存不能成为可信计算源。

### 4.2 存储与清除

数据存储在一次页面会话内固定后端。若 `localStorage` 写入失败，系统切换到内存后端并保持该选择，执行写后读验证，并向界面返回“本次会话临时保存”的明确状态。界面只有在读回成功后才报告持久化成功。

“清除本地数据”清理 records、sites、reports、institutions 与演示数据状态，保留语言和主题等个人偏好。报告缓存不再保存完整原始记录，只保存可重建的筛选条件、统计摘要和生成元数据。

“加载示例数据”先原子替换业务数据集，旧站点不会继续混入。机构版提供清晰的数据来源模式，演示数据和用户数据不互相覆盖；表格、汇总和报告显示当前来源。

### 4.3 风险与指标口径

未锁定模块统一采用锁定 `DecisionEngine` 的边界：NH₃ 高于 15 ppm 即进入紧急/高风险展示。风险标签、颜色、机构汇总、报告分布和建议保持一致。

原“氨气达标率”改为“项目舒适区占比”，并明确其 `<10 ppm` 的项目展示阈值，避免把项目阈值误称为法规达标结论。A/B/C 仅表达输入是否位于模型适用域，不再把合成测试集平均相对误差 `0.71%` 或 `5%` 表述为单条读数不确定度。模型说明改为“内部记录的合成测试结果；单点不确定度尚未评估”。

### 4.4 日期与报告结果

报告严格使用用户选择的日期范围。无数据时显示空结果说明，不静默扩展到全部历史；开始日期晚于结束日期时就地报错。报告补充站点数、有效样本数、拒绝数、数据来源、设备信息（若有）、模型版本、规则版本、生成时区和超出适用域的数量。

生成报告先在页面内形成可访问的预览。若浏览器阻止打印弹窗，状态提示真实说明失败，并保留预览与再次打印入口，不显示虚假的“报告已生成”。机构报告日期使用所选区间或数据区间。

## 5. 可视化与交互设计

### 5.1 趋势图

保留现有自定义图例，关闭 Chart.js 内置图例，消除重复视觉。五个图例项改为可键盘操作的按钮，点击后切换对应数据集并同步 `aria-pressed`，至少保留一个可见数据集。曲线颜色、单位和左右轴保持可辨识；隐藏状态不能只依赖颜色表达。

图表旁新增常驻文字趋势摘要，包含时间窗、最新值、最高 NH₃、变化方向和当前风险。`canvas` 提供可访问名称，并用 `aria-describedby` 关联趋势摘要和采样表。reduced-motion 状态下关闭 Chart.js 动画及非必要界面动效。

### 5.2 场景与流程

桌面场景预设默认收起为单个“演示”浮动按钮，展开后才显示五个场景，避免覆盖趋势图。任意导航操作仍会停止巡览。原“正常环境”改为“24 小时冬季基线”，准确反映该场景后段可能出现高氨风险。

流程条的三个可点击 `article role=button` 改为原生 `button`，删除重复的键盘模拟逻辑。`#pipelineNext` 在没有下一视图时使用原生 `hidden` 语义，并用 `.pipeline-next[hidden] { display: none !important; }` 保证 CSS 不会覆盖。

### 5.3 人工录入与反馈

六个人工录入字段使用持久可见的 `<label>`，显示单位、建议范围和错误信息；输入后字段含义仍然可见。关键控件在触屏上提供至少 44×44 px 的目标。导入、清除、报告生成和存储降级使用一致的状态反馈，并把错误关联到触发控件或字段。

## 6. 响应式与视觉设计

在不改变品牌主风格的前提下调整密度和层级：

- 390 px 及以下的传感器卡改为单列；状态 pill 独占一行；面板标题和点数统计允许合理换行。
- 六个底部视图入口在 320–430 px 全部可见，采用等宽紧凑布局和短标签，不依赖横向滚动；路由切换后仍确保活动项可见。
- 总览移动首屏压缩边界声明和流程条高度，实时指标优先于快捷入口。
- 桌面保持当前阅读宽度上限，不为了铺满 2560 px 而拉长图表和文本。
- 浅色主题减少灰雾、过重阴影和暗色发光；交互状态继续使用品牌青绿、清晰边框与层级，不增加装饰性渐变。
- 藏文使用系统可用的藏文字体回退栈，行高设为约 1.65，取消额外字距，并在按钮、表格和打印页提高最小字号。

## 7. 语义、键盘与读屏设计

页面提供首个可聚焦的“跳到主要内容”链接，并保留唯一 `<main id="main-content">`。路由切换后聚焦当前视图标题，`:focus-visible` 显示清晰的品牌色双层焦点环。

`snapshotList` 使用列表语义，子项使用 `role=listitem` 或原生列表项。高频传感器数值、规则命中和点数计数不使用 `aria-live`；只在导入结果、模拟完成、风险跃迁、存储降级和报告状态等高层事件播报。语言切换时立即刷新所有动态状态文本，不能等待下一次采样。

键盘顺序遵循视觉顺序；展开式演示菜单、图例按钮和移动导航均能用 Tab、Enter、Space 与 Escape 操作。

## 8. 性能与代码组织

把当前约 131 KB 的主内联脚本提取为 `dashboard.js`，保持原执行顺序与全局接口。依赖脚本按依赖顺序使用 `defer`；Chart.js CDN 增加 `preconnect`，继续保留已有 SRI 和本地降级逻辑。CSS 本轮只做必要重构，不进行全面样式框架迁移。

目标是在不牺牲图表和三语功能的情况下减少 HTML 解析阻塞。性能验收以前后 Lighthouse 中位数和真实手机视口为准，不能用单次高分替代功能回归。

## 9. 发布与站点发现性

GitHub Pages 改用 Actions artifact 发布：

1. `verify` job 在固定 Node LTS 环境运行单元测试、两个验证脚本、JS 语法检查和站点清单检查。
2. `deploy` job 使用 `needs: verify`，只有验证成功才上传和部署站点 artifact。
3. artifact 使用允许列表，只包含线上所需 HTML、JS、图像、CSV、文档与站点元数据，避免把测试和内部日志当作站点内容发布。
4. workflow 使用最小权限，第三方 actions 固定到完整提交 SHA。
5. CI 在发布前生成 `build_info.js`，写入真实 commit SHA 和 UTC 构建时间；本地回退值明确标记为开发构建。

站点增加 canonical、Open Graph 尺寸和类型、`robots.txt`、`sitemap.xml` 与自定义 `404.html`。断网场景改名为“已加载会话断网演示”，本轮不宣称离线刷新能力，也不添加空壳 manifest 或 Service Worker。

## 10. 测试设计与验收标准

新增回归测试覆盖：

- CSV 派生字段不能污染校准值。
- `__proto__`、`constructor`、超长或非法 `site_id` 不会崩溃或污染对象。
- localStorage 配额失败后会话固定降级，写后读可见且 UI 状态准确。
- 清除操作覆盖所有业务数据键并保留语言/主题。
- 示例加载真正替换旧数据，机构版不混合来源。
- 15–20 ppm 在决策、机构和报告中使用同一高风险等级。
- 无效时间、未来时间、反向日期范围和空日期区间按设计处理。
- 打印弹窗受阻时返回失败状态并保留页面预览。
- pipeline 隐藏按钮、主区域、跳转链接、图表名称、列表语义和标签存在。
- 三语动态状态即时刷新，藏文布局不溢出。
- 320、390、768、1440 和 2560 px 无页面横向溢出；390 px 六个底栏入口全部可见。
- 图例按钮可用键盘切换，`aria-pressed` 与曲线显示同步。

最终验证包括：

- `node --test tests/*.test.js`。
- `node verify_compensator.js` 与 `node verify-deployment.js .`。
- 所有非锁定 JavaScript 文件执行 `node --check`。
- 对五个锁定文件进行修改前后 SHA-256 对比。
- 中英藏三语、深浅主题、键盘、读屏、打印和 popup 受阻场景的真实浏览器检查。
- 桌面、平板和手机截图；Lighthouse 性能、无障碍、最佳实践和 SEO 前后对比。
- 推送后等待验证与 Pages deployment 成功，再核对线上 SHA、控制台、`online_test.html` 和主要交互。

完成标准：所有现有测试与新增测试通过；锁定文件哈希不变；没有已知 P1；Pages 线上版本与最终提交一致。

## 11. 风险与回滚

- **脚本提取顺序风险**：先以行为测试锁定现有全局初始化顺序，再提取脚本；任何回归可单独回退该提交。
- **旧 localStorage 数据兼容**：读取时规范化并忽略不可信派生字段，避免直接删除用户原始记录；清除动作仍由用户触发。
- **Pages 工作流切换风险**：在部署 workflow 合并前验证 artifact 内容和入口；旧分支内容保留，可回滚到上一工作流。
- **视觉密度回归**：使用多视口截图比较，不以单一桌面宽度作为验收。
- **报告口径变化**：在界面和 README 中同步解释“项目舒适区占比”和模型指标来源，避免用户把术语变化理解为算法改变。

## 12. 明确不做

本轮不实现真实账号体系、服务端数据库、云同步、多租户权限、硬件控制闭环、模型再训练、法规认证、完整 PWA 离线缓存或前端框架重写。这些工作需要独立的安全、数据和运维设计，不能作为静态演示站的顺手扩展。
