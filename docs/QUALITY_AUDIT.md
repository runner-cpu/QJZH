# 质量审计与工程边界

> 审计基线：2026-10-07。本文记录公开静态分析工具的工程加固结果、验证方法和仍然存在的使用边界。内容只描述产品、数据和发布流程，不包含未授权的背景信息。

## 1. 审计范围与结论

本轮从数据可靠性、前端安全、可访问性、视觉节奏、版本治理、性能、浏览器兼容性、隐私、文档治理和 Pages 发布链路等角度复核项目。结论不是“系统可以替代人工判断”，而是：在浏览器本地运行、输入数据先校验、发布物经过白名单构建和提交哈希核对的前提下，主要故障路径都有可观察的失败状态和可重复的复核入口。

| 维度 | 已加固的控制 | 验证入口 | 仍需使用者注意的边界 |
| --- | --- | --- | --- |
| 输入与数据质量 | 文件预检、字段白名单、大小/行数/字段长度限制、时间区间校验、派生值重算 | `tests/round9_data_trust.test.js`、`docs/DATA_DICTIONARY.md` | 不完整或未经校准的原始记录仍会降低解释价值 |

## 2. 版本、缓存和报告追溯

项目把容易混淆的身份拆成四层：

- `releaseVersion`：面向用户的页面发布版本，采用 `YYYYMMDD`，用于普通静态资源缓存键。
- `deploymentVersion`：一次具体部署构建的标识，CI 使用 `build-<run>`，本地构建使用提交短 SHA 派生值或 `dev`。
- `modelVersion`：`model_weights.js` 声明的语义版本；补偿实现和模型资源使用这一版本缓存键。
- `rulesVersion` 与 `rulesFingerprint`：知识库规则版本名和规范化内容的 SHA-256。

同时保留 `version` 作为旧集成的兼容别名，但它只等于 `deploymentVersion`，不再代表模型或规则。`commit`、`builtAt` 和 `environment` 用于追踪实际发布物。报告、自检页和 `artifact-manifest.json` 都应能沿这条链路回到源提交。

修改页面资源后，必须同步页面 meta、资源查询参数、构建元数据契约和测试；不能只改一个版本字符串。发布前优先比较 `build_info.commit` 与目标提交的完整 SHA，而不是依据浏览器缓存中的标题或时间。
本轮发布版本已统一更新为 `20261007`：两张页面的 meta、本地 `build_info.js` 和普通静态资源查询参数保持一致；锁定模型资源继续使用独立的 `1.0.0` 查询键，不随界面发布版本漂移。

自检页的版本信息按复核问题分成四个可见层级：

1. **构建来源**：运行环境、提交 SHA 和 UTC 构建时间，用来确认页面来自哪里。
2. **发布与部署**：发布版本负责静态资源缓存键，部署版本负责标识一次 CI 构建实例。
3. **执行契约**：模型版本对应锁定权重接口，规则版本对应知识库规则集。
4. **规则完整性证据**：规则 SHA-256 指纹单独展示，明确它是内容证据而不是第五种版本号。

这组字段使用文本说明和可复制值建立语义，颜色只作弱辅助；移动端会按同一顺序堆叠，避免连续的高饱和色卡把不同身份误读为同一种版本。

## 3. 视觉层级与模块节奏

首页快捷入口按“核心分析链路”和“扩展与输出”分组，采用等宽网格和轻量色调差异，避免同一种卡片连续堆叠造成视觉噪声。中等宽度使用两列布局，小屏降为单列；按钮和关键控件保持至少 44px 高度。

视觉约束如下：

1. 颜色只表达状态或分组，风险等级仍以文字和可读摘要重复表达。
2. 动画只用于状态转换和空间关系，`prefers-reduced-motion: reduce` 时关闭非必要位移和渐变。
3. 图表失败时保留表格、文字摘要和报告导出，不把 Canvas 当作唯一信息载体。
4. 不通过禁用右键、拦截键盘、隐藏焦点或干扰屏幕阅读器来实现所谓的防复制。

## 4. 可访问性与多语言

页面保留跳转主内容链接、唯一 `main` 地标和可定位的视图标题。导入、导出、报告预览等异步流程会同步可见状态、`aria-live`、`aria-atomic` 和 `aria-busy`，完成或失败后把焦点交还给状态摘要或重试控件。所有手动输入都有可见标签和帮助说明，键盘路径不依赖 hover。

中文、英文和藏文状态键集中在 `ui_text_map.js`；语言切换会更新页面 `lang`、标题、状态摘要、表头和图表文字。动态内容优先使用 `textContent`，结构化报告只允许经过审计的转义函数。

## 5. 数据可信度与存储恢复

CSV 进入 `FileReader` 前会检查名称、可读性、空文件、字节数和扩展名边界；解析阶段限制字段、行数和单元格长度，时间戳必须带明确偏移。导入值只作为原始输入保存，校准值、风险等级和建议由当前锁定版本重新计算，并记录来源计数。

多站点保存前建立本批次快照；任一站点写入失败时回滚本批次涉及的业务键，保留原有记录，并明确返回降级后的存储模式。导出只读当前业务记录，使用固定字段顺序和 CSV 引号规则。清除操作要求显式确认，只删除 `QJZH_` 业务键，不触碰语言和界面偏好。

## 6. 前端安全与隐私边界

当前公开页面没有账户、远端数据库或默认上传接口。输入、规则说明、来源标签、报告字段和版本信息均视为不可信文本；写入 HTML 前必须转义，颜色、状态 class、百分比和数量必须经过 allowlist 或数值钳制。报告打印按钮通过 `data-action` 与事件监听器绑定，不把用户内容放入 inline handler 或 `javascript:` URL。

外部依赖只保留审计过的 Chart.js 版本并校验 SRI。`.well-known/security.txt` 提供最小化的安全问题报告入口；报告问题时不得上传原始敏感数据、凭据或完整业务文件。更具体的响应时限、数据生命周期和公开边界见 [SECURITY.md](../SECURITY.md)。

## 7. 性能、兼容性与降级

这是无构建依赖的原生静态前端：外部脚本使用 `defer`，锁定模型资源先于依赖它们的展示逻辑加载，图表库固定版本并提供文本/Canvas 回退。导入硬限制和报告只保留汇总缓存，避免把完整 CSV 写入报告缓存。

验证重点包括：

- Chromium、Firefox、Safari 的现代版本能运行标准 DOM、`FileReader`、`URL`、`fetch` 和 `localStorage` 路径。
- 隐私模式、配额不足、文件读取中止和弹窗被拦截时，页面仍给出可翻译状态和可重试入口。
- 长列表和图表不应阻塞首屏；超过输入预算的文件在读取前拒绝。
- 线上资源的版本查询参数与发布版本一致，模型资源与模型版本一致。

浏览器兼容性不是对旧版内核的承诺；若使用不支持的能力，应优先采用文本结果和明确错误提示，而不是静默给出空结果。

## 8. CI/CD、artifact 与运维复核

GitHub Actions 在 UTC 环境运行测试和构建。`scripts/build-pages.js` 只复制审计过的公开文件和文档，显式排除测试、内部计划、临时输出、备份和符号链接；构建后生成 `.nojekyll` 与排序的 `artifact-manifest.json`，逐文件记录字节数和 SHA-256。`verify-deployment.js` 在上传前核对路径、文件、摘要、版本契约、脚本顺序、SRI 和公开文案。只有验证成功的 artifact 才能进入 Pages 部署。

本轮同时移除了公开源码中的内部方案草稿和执行日志，并在 `.gitignore` 中屏蔽对应路径；它们不属于产品文档，也不进入 Pages artifact。公开说明只保留可复核的产品边界、工程控制和使用限制。

部署后 `scripts/smoke-pages.js` 以固定 URL 清单检查主页、自检页、版权、原创性、安全、数据字典、构建元数据、robots、sitemap、security.txt 和 manifest，并可按指数退避重试。若传入预期提交 SHA，它还会拒绝线上 `build_info.commit` 不匹配的页面。

故障处理顺序：保留失败 run 和 manifest，确认 Pages source 仍为 workflow，比较线上提交 SHA 与目标提交；修复源文件后重新构建，不手工覆盖线上 `build_info.js`。

## 9. 版权、原创和完整性

项目采用根目录 `LICENSE`、`COPYRIGHT.md`、`ORIGINALITY.md` 和 `originality-manifest.json` 共同约束。受保护文件的规范化 SHA-256 在发布前重新生成并校验；新增核心实现、构建器或安全校验脚本时，必须把它加入受保护清单。

防止未经授权复制的措施是可审计的法律和工程措施：明确许可边界、保留版权与来源声明、提交和 artifact 摘要、公开安全响应渠道、发布前完整性校验和变更审计。页面不采用会伤害键盘或辅助技术的反交互脚本。

## 10. 测试与已知边界

常规收尾命令如下：

~~~text
$env:TZ = "UTC"
node --test tests/*.test.js
node verify_compensator.js
node scripts/verify-originality.js
node verify-deployment.js .
node scripts/build-pages.js --out dist
node verify-deployment.js dist
git diff --check
~~~

回归测试覆盖输入限制、存储回滚、导出、清除确认、动态转义、颜色白名单、语言状态、键盘焦点、确定性展示、版本契约、artifact 清单和 Pages smoke stub。它们不能替代真实浏览器中的屏幕阅读器测试、真实配额耗尽、真实 CDN 中断和线上传播窗口观察；这些场景应在发布抽查中记录结果。

## 11. 后续审计优先级

1. 每次规则、模型或公开资源变更都同步更新版本契约和哈希清单。
2. 每次新增动态输出都先补一个恶意文本回归样例，再实现渲染。
3. 每次发布都保留 artifact manifest、workflow run 和线上 SHA 证据。
4. 定期复核外部 CDN 的固定版本与 SRI，发现供应链变更时先停发。
5. 由真实键盘和辅助技术使用者复核新视图，不把自动化结构测试当作完整可访问性证明。

## 12. 本次专项复核：30 个维度

本次从基线提交 `9c9ad38` 开始复核。原有 96 项自动测试全部通过，但新增的数据完整性复现用例在修复前暴露了真实缺陷；因此本轮同时增加行为测试、真实浏览器操作与 WCAG 扫描，避免只以源码字符串断言判断产品质量。以下结论以代码检查、故障注入和浏览器观测为依据。

| 维度 | 发现的不足或复核结果 | 本次处理与证据 |
| --- | --- | --- |
| 1. 产品定位与结论表达 | 机构页把 NH₃ < 10 ppm 的站点比例称为“达标率”，容易被理解为合规结论 | 改为“低风险站点占比”，告警数量按站点数表述；锁定模型与规则继续使用原接口 |
| 2. CSV 结构 | 未闭合引号、引号后残留字符、数据列数多于表头仍可能通过 | 严格解析引号与列数，保留合法引用换行；`tests/data_integrity.test.js` |
| 3. 文件与空输入 | 只有表头可返回无错误，预检没有验证扩展名 | 拒绝空数据集与非 .csv 文件；1 MiB / 5000 行 / 11 列 / 256 字符预算保持明确 |
| 4. 日历与时间语义 | JavaScript 会把 2 月 30 日或 24:00 归一化为其他时间 | 显式校验真实日期、时分秒及偏移；拒绝归一化日期；报告继续使用上海完整自然日 |
| 5. 数字与可选元数据 | 空白或十六进制可能被转换为数字；可选数值未校验 | 使用十进制语法，拒绝非有限值、负元数据和小数日龄；小数湿度可在表单录入 |
| 6. 去重与输入规范化 | 带不同偏移的同一时刻、站点外侧空格会产生重复记录 | 去重键使用标准化时刻与站点；保存原始合法时间文本，重复时新值替换旧值 |
| 7. 数据容量与完整性 | 可导入 5000 行，保存却静默截成每站 1000 行 | 完整保留 5000 条；累计超限整批失败并明确提示，支持导出后清理；5000 行回归通过 |
| 8. 示例替换事务 | 示例先清空旧记录，之后的写入失败无法恢复原值 | 替换操作与删除过期键放在同一批快照内；失败恢复原记录和报告键，验证恢复结果 |
| 9. 保存失败反馈 | 人工录入只检查 valid，可能把配额失败显示成保存成功 | 传播 ok、code、rolledBack；仅成功保存后触发导入事件；增加故障注入测试 |
| 10. 清除与重置 | removeItem 失败被吞掉；重置替换内存对象但导入器仍引用旧对象 | 验证逐键删除结果；重置复用同一清除接口；失败保持可观察状态 |
| 11. 浏览器存储兼容 | localStorage / sessionStorage 属性本身抛错时无法降级 | 安全访问存储属性，受限环境使用内存；真实浏览器通过保存与重置验证 |
| 12. 坏数据隔离 | 一个坏 JSON 会将整个页面切到空内存；非数组数据可能令聚合崩溃 | 隔离坏键、校验存储形状和记录，保留正常站点，显示损坏项数量，不删除原始坏键 |
| 13. 隐私与数据生命周期 | README 声称刷新会清空数据，与默认本地持久化不一致 | 修正文档，页面显示存储方式、记录数和不上传说明；明确浏览器存储不是备份 |
| 14. 导入审阅与撤销 | 选择文件立即写入，用户无法先核对有效行与错误 | 增加前 20 行预览、有效/拒绝/警告计数和确认/取消；保存前不改原记录 |
| 15. 破坏性演示动作 | 加载示例和重置可能直接覆盖用户记录 | 用户数据存在时增加明确确认；取消保留全部记录，内置示例重复加载保持去重 |
| 16. 异步时序 | 较早 FileReader 回调可能覆盖之后的选择或清除操作 | 用读取批次标识过滤过期回调，清除/替换/取消时中止读取，同一文件可重新选择 |
| 17. 操作状态与多语言 | 动态状态带静态翻译属性，语言切换会把成功信息恢复成空状态 | 保存状态语义、数量与当前语言；新增三语预览/校验/存储消息，错误详情重新解析翻译 |
| 18. 数据可读性 | 0 ppm 使用 `value || '-'` 被显示成缺失值 | 用空值判断保留零值；错误详情用文本节点，预览与表格保持转义 |
| 19. 跨标签页一致性 | storage.clear() 的空 key 事件被忽略；回放缓存与机构结果可能滞后 | 空 key 和业务键事件都会使回放失效并刷新摘要、机构和报告；真实双标签页验证 |
| 20. 机构聚合正确性 | 最新氨气可与旧温湿度混合，且输入无序时会选错采样 | Map 分组，按时间选择最新整条记录，样本量独立累计，校准值重新计算；来源不混入演示快照 |
| 21. 报告日期与可发现性 | 旧示例超出默认 90 天，首次生成可能看起来没有数据 | 有记录时建议完整数据日期范围；手动选择后保留用户日期；无记录时使用最近 90 天 |
| 22. 报告状态与一致性 | 非法日期仍留着旧预览，数据改动后可继续打印旧报告 | 生成后始终保留当前预览；非法日期或数据变化清除旧预览；切换语言更新报告与状态 |
| 23. CSV 导出安全 | 引号转义无法阻止电子表格执行公式；下载 URL 撤销过早 | 公式起始文本加单引号转义，重导入恢复一层；延后撤销 URL；真实下载内容校验 |

### 本轮验证入口

`tests/data_integrity.test.js` 覆盖数据损失、严格解析、时间等价、事务回滚、人工配额失败、损坏存储、公式导出、清除失败、机构最新采样、缓存失效和报告缓存降级。原有功能、模型、治理和发布测试一并运行。

`scripts/browser-check.mjs` 以 `/QJZH/` 子路径服务构建产物，检查 108 组布局与 WCAG 2.1 A/AA 自动规则，并执行预览确认、取消、部分导入、真实下载、刷新、机构来源、报告弹窗拦截、无效日期、三语预览、人工录入、覆盖确认、跨标签页清除、受限存储及 Chart.js CDN 中断路径。证据输出到 `output/browser-audit/`；这些开发文件和截图不发布到 Pages。

### 尚存的具体边界

1. 现有锁定模型只验证声明的领域范围；B 级边界输入并不意味着外推准确。本轮没有改变模型权重或知识规则，实地泛化能力仍需真实验证数据。
2. localStorage 的批量快照不是数据库事务；浏览器整体故障、配额阻断恢复或同时在多个标签页写入不能获得数据库级隔离保证。需要多人同时录入时，应另行设计存储层。本轮能识别并报告恢复失败。
3. 损坏的站点索引无法自动推断完整历史。本轮保留坏键并告警，避免静默清空；此前已被旧版本截断的历史无法由此次升级凭空恢复。
4. 网页首次打开需要静态资源可达。图表 CDN 失败有本地 Canvas 回退；完整网站首次离线加载、设备采集或后台同步并未由此实现。
5. WCAG 自动扫描不能代替真实屏幕阅读器和人类阅读评估。藏文语义仍需母语使用者复核；本地验证以 Chromium 为主，其他内核仍应在后续发布抽样。
6. dashboard.js 与内联 CSS 仍较大，部分原有层叠规则和兼容逻辑存在维护成本。本轮集中修复可复现缺陷，后续可按行为边界拆分模块，但拆分需要完整回归保护。
7. 不同站点的报告趋势属于汇总展示，不能被当作同一传感器连续采样序列。站点对比与样本量不均衡仍需结合原始记录解释。

升级后应优先查看最新 `build_info.commit`、Actions 浏览器证据和本节，而不是把旧截图或基线测试通过等同于当前发布已验证。
